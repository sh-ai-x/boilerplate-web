Runtime override. Adapter selection happens at request time via getAuthAdapter() / getDbAdapter(). The highest-priority env var is AUTH_PROVIDER (values: clerk | none) and DB_PROVIDER (values: supabase | neon). If unset, detection falls back to env-key presence, then defaults. This means you can switch adapters after scaffold without re-running the CLI — just set the env var, redeploy, and the new adapter takes over. See Step 9 below.

Step 0 - Scaffold (one line)

Replace --auth, --db, and --deploy-target based on your matrix row above. Drop any flag you don't care about — it defaults to clerk / supabase / vercel.

# default (clerk + supabase + vercel)
npx create-boilerplate-web ./my-saas --type=saas --yes --allow-unsafe-path --skip-install --deploy

# minimal (no auth + neon + no deploy workflow)
npx create-boilerplate-web ./my-saas --type=saas --auth=none --db=neon --deploy-target=none --yes --allow-unsafe-path --skip-install

What this does: clones templates/saas/ + templates/_shared/, writes pnpm-workspace.yaml, rewrites the project's package.json "name". The --auth=none / --db=neon / --deploy-target=none flags cause the CLI to delete files that don't apply (Clerk pages, Supabase migrations, GitHub Actions workflow) and write .boilerplate.json recording your choice.

Step 4 - Create DB project supabase neon

Follow only the one panel that matches --db.

--db=supabase 
supabase.com/dashboard -> New Project
  1. supabase.com/dashboard → New Project. Pick name + region. Save the DB password somewhere.
  2. From the project dashboard, copy 3 keys:
    • Settings → API → Project URL → NEXT_PUBLIC_SUPABASE_URL
    • Publishable key (starts sb_publishable_) → NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY
    • Secret key (starts sb_secret_, server-only) → SUPABASE_SECRET_KEY
  3. From Settings → General, copy the Reference ID (20-char slug in the URL) → this is your SUPABASE_PROJECT_REF.
  4. From account/tokens, Generate new token (one per Supabase account, reusable across projects) → SUPABASE_ACCESS_TOKEN.
  5. Wire Clerk as Supabase third-party auth (only if --auth=clerk):
    1. Supabase dashboard → Authentication → Sign In/Up → Third Party Auth → Add provider → Clerk.
    2. Paste your Clerk JWKS URL:
      • Dev: https://<your-frontend-api>.clerk.accounts.dev/.well-known/jwks.json
      • Prod: https://clerk.<your-domain>/.well-known/jwks.json
    3. Find your frontend API at dashboard.clerk.com → API Keys → "Show frontend API" (or derive from pk_test_xxx → xxx.clerk.accounts.dev).
    4. Save the same URL into SUPABASE_JWKS_URL in .env.local (used by self-hosted Supabase deployments).

    After this, RLS policies can read the Clerk user id via auth.jwt() ->> 'sub'.

--db=neon 
console.neon.tech -> New Project
  1. console.neon.tech → New Project. Pick region. Default Postgres 16 is fine.
  2. From the project dashboard, click Connection Details → toggle to Pooled connection → copy the connection string into DATABASE_URL.
  3. Run schema migration after Step 6: 
    pnpm drizzle-kit push

    Replaces supabase db push. The Drizzle schema lives at templates/_shared/adapters/db/schema.ts in the repo; the scaffold copy is in your project root.

  4. No Edge Functions. If a feature previously called a Supabase Edge Function (e.g. billing), you must port it to a Next.js Route Handler at app/api/billing/route.ts. The Neon adapter doesn't proxy .rpc() to Edge Functions.

Step 9 - Override adapters at runtime optional

You can switch adapters after scaffold without re-running the CLI. The highest-priority signal is the env var; the runtime re-detects on next request.

# In .env.local (or Vercel project settings):

# Switch off Clerk without re-scaffolding
AUTH_PROVIDER=none

# Switch from Supabase to Neon
DB_PROVIDER=neon
DATABASE_URL=postgres://user:pass@ep-xxx.neon.tech/mydb

# Remove deploy workflow without re-scaffolding
# (not reversible at runtime -- you need to re-add the workflow file from the repo root)
How detection resolves. getAuthAdapter() reads in order: (1) AUTH_PROVIDER env, (2) NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY present, (3) default to clerk. getDbAdapter() reads in order: (1) DB_PROVIDER env, (2) NEXT_PUBLIC_SUPABASE_URL present, (3) DATABASE_URL starts with postgres://, (4) default to supabase. Source: templates/_shared/adapters/<auth|db>/index.ts#detectKind().
Adding a new adapter (advanced). Create templates/_shared/adapters/<auth|db>/<provider>.ts implementing the interface (see types.ts), then add one line to the factory's detectKind(). Consumer code is unchanged.
