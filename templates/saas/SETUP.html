Step 0 - Scaffold (one line)

npx create-boilerplate-web ./my-saas --type=saas --yes --allow-unsafe-path --skip-install --deploy

What this does: clones templates/saas/ + templates/_shared/, writes pnpm-workspace.yaml, rewrites the project's package.json "name".

Step 1 - Install deps pnpm

WARNING: do not run npm install. The workspace:* protocol in package.json is pnpm-only - npm fails with EUNSUPPORTEDPROTOCOL.
cd ./my-saas
npm install -g pnpm     # if you don't have pnpm
pnpm install

cp .env.example .env.local

Step 3 - Configure Clerk clerk

  1. dashboard.clerk.com → Create Application (name: anything, enable Email + Google + GitHub).
  2. Copy API keys (left nav: API Keys) into .env.local now if you haven't already.
  3. Configure sign-in paths (left nav: Account & Sessions → Paths):
    • Sign-in URL: /sign-in
    • Sign-up URL: /sign-up
    • After sign-in: /
    • After sign-up: /
  4. Create a webhook (left nav: Webhooks → Add Endpoint):
    • URL: https://<your-deployed-domain>/api/webhooks/clerk (use a placeholder for now - you'll update after first deploy)
    • Events: tick user.created, user.updated, user.deleted
    • Copy the Signing Secret (starts whsec_) into CLERK_WEBHOOK_SECRET
Test mode only: Clerk's test keys (pk_test_..., sk_test_...) work without payment. For production, copy the live keys (pk_live_, sk_live_) when you go live.

Step 4 - Create Supabase project

  1. supabase.com/dashboard → New Project. Pick name + region. Save the DB password somewhere.
  2. From the project dashboard, copy 3 keys:
    • Settings → API → Project URL → NEXT_PUBLIC_SUPABASE_URL
    • anon public → NEXT_PUBLIC_SUPABASE_ANON_KEY
    • service_role → SUPABASE_SERVICE_ROLE_KEY
  3. From Settings → General, copy the Reference ID (20-char slug in the URL) → this is your SUPABASE_PROJECT_REF.
  4. From account/tokens, Generate new token (one per Supabase account, reusable across projects) → SUPABASE_ACCESS_TOKEN.

Step 5 - Cloudflare + Toss accounts

Two short sign-ups. Do them in parallel - both take <2 min.

Cloudflaresign-up → add a domain (free plan OK) → note Account ID + Zone ID
Tosstosspayments.com → sign up with corp info → developer dashboard → issue Live Secret + Live Auth keys
Toss test mode: use _test_-suffixed keys for development. Real cards still work in test mode - this only suppresses real-money capture.

Step 6 - Run setup (one command)

Will run supabase link, supabase db push, deploy the billing Edge Function, init git, push to GitHub, set 7 repo secrets.
export GH_REPO_NAME=my-saas
./scripts/setup.sh --check    # verifies prereqs first (dry-run)
./scripts/setup.sh            # actually does it
Pre-req: supabase login + gh auth login must already have been done. Setup.sh aborts if either is missing.

Step 7 - Update Clerk webhook URL

You set a placeholder URL in Step 3. After the first deploy, you have a real domain. Update Clerk:

  1. Open dashboard.clerk.com → Webhooks → your endpoint.
  2. Paste your Vercel URL + /api/webhooks/clerk → Save.
  3. Click Send test event → verify 200 OK in the response.
Tip: alternative is to use a tunnel service (cloudflared tunnel or ngrok http 3000) for local webhook testing before deploy.

Step 8 - Watch first deploy

gh run watch --repo "<OWNER>/<REPO>"

4 jobs run in parallel:

  • vercel-deploy - Next.js build + push to Vercel
  • cloudflare-pages-deploy - alternate deploy target (skipped if CF_API_TOKEN is missing)
  • supabase-functions - deploys the billing Edge Function
  • cloudflare-waf - applies 6 WAF rules from cloudflare-rules.json
